# Chia việc theo module — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** QA chia việc theo module (nhóm màn hình); tester tự nhận module (chỉ cảnh báo khi đã có người làm); import chọn module và tự tạo màn hình còn thiếu.

**Architecture:** Thêm tab `Modules` và `ModuleAssignments` vào Sheet dự án, cột `module_id` cho `Screens`. Việc giao theo màn hình (`Assignments`) giữ nguyên và vẫn quyết định quyền/kết quả; một `ModuleWorkService` mới tự tạo/xoá các dòng `Assignments` từ `ModuleAssignments`. Import nhận thêm `module_id` để so khớp màn hình trong module và tự tạo màn hình mới.

**Tech Stack:** FastAPI, Google Sheets (qua `SheetTable`), Redis lock (`redis_lock`), pytest + fakeredis + `FakeSheetsGateway`; Next.js 16, TanStack Query, next-intl (`messages/vi.json`), vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-modules-design.md`

## Review Focus

1. Import cùng một tên màn hình mới ở nhiều nhóm dòng (hoặc khác hoa/thường, thừa khoảng trắng) → chỉ tạo **một** màn hình. Test ở Task 5.
2. Import lại sau lần ghi case lỗi (màn hình rỗng đã tạo) → khớp tên với màn hình đó, không tạo trùng. Test ở Task 5.
3. Tester đã nhận module, QA thêm màn hình vào module sau đó → tester được tự giao và sửa/chạy case được như thường. Test ở Task 3.
4. Bỏ nhận module khi tester có case trên màn hình → case giữ nguyên, việc giao mất. Test ở Task 4.
5. Tester bị bỏ khỏi dự án / ngưng hoạt động nhưng còn dòng `ModuleAssignments` → import của người khác vào module vẫn chạy, không giao cho người đó. Test ở Task 4 và Task 5.
